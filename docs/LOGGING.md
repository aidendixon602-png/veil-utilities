# Server logging

Veil routes server events to configured channel IDs or matching Veil log channels (`#join-logs`, `#command-logs`, `#message-logs`, `#member-logs`, `#role-logs`, `#channel-logs`, `#voice-logs`, `#veil-utilities-logging` / `#server-logs`, `#antinuke-logs`, `#mod-logs`, `#mute-logs`), while automatically skipping Ghost Vanguard channels (`#bans` and channels under `Ghost Vanguard Logs`) unless an owner or bot developer explicitly overrides and approves them.

`,logs` opens the interactive logging panel (restricted to the server owner and bot developers) where you can pick a category, assign a channel, create missing channels, switch a category to `off` or `auto`, or toggle role-blacklist reply DMs. `,logs list` shows a text summary, `,logs test` sends test cards, `,logs set <category> #channel` sets a destination directly, `,logs off <category>` disables a route, and `,logs auto <category>` resets a category to automatic/shared routing. Check channel visibility and bot View Channel, Send Messages and Embed Links permissions. Bulk transcripts additionally need Attach Files.

## Setup and cleanup

`,logs setup` (and automatic setup when enabled via `auto_log_setup`) creates a private `VEIL LOGS` category and any missing default channels (`join-logs`, `command-logs`, `veil-utilities-logging`, `antinuke-logs`, `role-logs`, `channel-logs`, `voice-logs`, and `mod-logs`), reusing existing Veil log channels and leaving disabled (`off`) routes untouched. `,logs cleanup` lists duplicate or leftover catch-all log channels without deleting anything; `,logs cleanup delete` removes only unused leftover catch-all channels and never touches active routes or Ghost Vanguard channels.

## Routes and exclusions

Explicit approved IDs take precedence. A positive but unreviewed, deleted or otherwise unresolved ID stops that category rather than falling through. `off` stops that category. When unset, joins/leaves may share the approved members destination, members the approved joins/leaves destination; messages, roles, channels and voice may share the approved server destination; timeouts may share approved moderation. Commands, moderation, server and antinuke have no shared fallback. An approved destination can be selected regardless of its name or category. Moving a destination or changing permissions later may affect delivery; review them periodically.

The exclusion lists are applied where listeners pass a source user/channel. Messages, voice and commands supply both where available; member, ban, timeout and member-role events use the subject user. Server-wide role/channel/invite/emoji events have no subject-user exclusion guarantee. Antinuke and the separate case/modlog streams have their own routing and may bypass server-log exclusions. Bulk message transcripts exclude ignored users, bots and Veil-cleaned messages. Logs contain message text and attachments, user IDs and moderation details. Restrict readers, consider consent and retention, and avoid logging channels with sensitive material. Scrubbing removes known secrets but is not comprehensive; no redaction guarantees arbitrary private information is removed.

Events depend on Discord intents and permissions, cache state and API delivery. Message edits/deletions and bulk events use cached messages; message-content and member intents may be restricted. Audit attribution is a best-effort correlation, not proof; message deletion cards do not name an actor because audit records can be aggregated. Delayed audit entries, simultaneous actions, restarts and unavailable audit permissions can omit or misattribute details. Delivery is not durable: failed sends are warned locally, but events can be lost and are not retried. Notifications can be duplicated by other systems. Normal log sends suppress mentions. Test safely in a disposable server, not production.

Separate developer error/auth channels are managed by `core/devchannels.py`, not this server logging configuration. Automatic startup provisioning is disabled; existing stored IDs and `AUTH_LOG_CHANNEL` / `ERROR_LOG_CHANNEL` overrides remain usable. The internal provisioning helper still performs name-based category reuse and movement of stored channels and must not be used until separately reviewed. Antinuke's explicit alert channel and the case modlog are likewise separate destinations. This change does not modify external integrations or protection exemptions.
