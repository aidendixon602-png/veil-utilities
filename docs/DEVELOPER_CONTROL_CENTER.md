# Developer control center: implementation status

## Audit and prioritized plan

1. Restrict all existing dashboard routes and saves to Veil developers, recheck Discord-discovered identities, revoke sessions on logout/restart, and retain OAuth, CSRF and HTTPS protections. Do not alter bot command permissions.
2. Reorganize navigation and present real bot/server information; preserve the server feature, Roblox group and authorization workflows.
3. Add bounded, read-only views of existing moderation cases and security incident records. Avoid rendering arbitrary reason/details fields and credentials.
4. Expand only after identifying shared, authorized backend services, adding audit/confirmation/state rechecks and testing partial failures. Do not simulate unimplemented monitoring, recovery or destructive operations.

The existing UI is server-rendered `aiohttp`, with embedded CSS and a small same-origin JS file; there is no frontend framework or WebSocket route. Routes and OAuth/session logic are in `core/dashboard.py`, forms in `core/dashboard_features.py`, the public Roblox lookup in `core/dashboard_roblox.py`, and data in the existing `core/db.py` SQLite/PostgreSQL adapters. The bot's developer identities are configured `OWNER_IDS`, built-in `BOT_DEVELOPERS`, and the Discord application owner/accepted team. The dashboard does not use server ownership, Discord Administrator, Veil ranks, fake permissions, or Antinuke trust to authorize access.

## Changes and limits

The overview reports gateway readiness, process uptime, joined and authorized server counts, and open/containing incident *records*, where available; none is a guarantee of service health or ongoing attacks. The searchable server inventory and existing settings pages remain. The control center links to real per-server security, logging and Roblox settings. Moderation shows 25 cases per page, selected by joined server; incident records show the latest 25 for the selected server. Case reasons and incident details are omitted, not exposed in raw logs. Database status is only a `SELECT 1` query, and the cog list is the bot's current in-process view.

This is **not the complete requested rebuild**. Missing features include Roblox monitoring, raid detection, lockdown, snapshots, comparisons, scheduling and recovery; searchable/paginated full logs; moderation actions/history beyond stored cases; API health probes; backup/restore controls; remote session management; cross-server operations; durable dashboard audit history; and the requested complete design/accessibility and mobile/browser validation. No Roblox credentials are stored, so encrypted credential storage is not implemented. Unknown/unavailable status is not represented as healthy, and no unsupported action is offered. The incident store is not necessarily a complete history of all security events. Existing Antinuke remains best effort and restoration can be incomplete.

The existing OAuth protocol is unchanged, but old sessions are invalidated. New sessions use an in-memory registry and last 12 hours. Logout invalidates that session in this process; restart invalidates all sessions. There is no multi-process or durable session revocation. Every request rechecks developer access, and existing saves recheck immediately before writing. Rate limits are process-local, bounded and use the TCP peer (anonymous) or session user ID; all visitors behind a common proxy can share one anonymous bucket. They do not replace upstream rate limiting or a shared session store. Dashboard request logging avoids URLs, request data, credentials and OAuth codes; host-level access logs and proxy configuration must be reviewed separately. Existing dashboard save locks are process-local and are not cross-process compare-and-swap; uncertain database outcomes require review before retrying.

Roll back by disabling `DASHBOARD_ENABLED` or deploying the previously verified version through the normal operator process. Rolling back restores the *previous owner/developer dashboard access policy*, so disable the dashboard until the previous behavior is explicitly reviewed. No schema migration is required. Do not restart/deploy production without authorization; set `AUTO_SYNC_GIT=0` in the process environment before starting a local bot. Live Discord OAuth, real Roblox API connectivity, production data and browser layouts have not been tested by these changes.

## Local verification

- Developer access, OAuth flow with mocked Discord, session/logout, request limiting, Roblox dashboard, tunnel and self-role command tests: 48 passed. The developer-only cases include denied server owners and nondevelopers, accepted versus invited team members, stale cookies, revocation, CSRF and server-scoped case access.
- Full local suite: 1,368 passed, 46 failed, 1 skipped. A fresh test run of this branch's base commit produced the same 46 failure identifiers (1,360 passed, 2 skipped). Existing failures are primarily logging, dashboard logging and strip-card tests and remain unresolved. The older dashboard tests were updated where their server-owner access expectations conflicted with the new policy; bot permissions were not changed.
- Ruff, generated-command reference check and `git diff --check` passed. No real Discord OAuth, Roblox API, deployed service or desktop/mobile browser testing was performed. This work is not ready to be described as the complete requested rebuild.
